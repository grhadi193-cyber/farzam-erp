# پنل ERP فرزام — نسخه مستقل سروری (Farzam ERP   Server)
سیسیسیسی
نسخهٔ مستقل و قابل نصب روی سرورِ پنل مالی فرزام: یک وب‌اپلیکیشن فارسی و راست‌چین که کارمندها رویدادهای مالی را با **یک پیام آزاد** («خریدیم…»، «فروختیم…»، «حقوق فلانی…») ثبت می‌کنند و ایجنت (Pip) از طریق API اختصاصی خودش آن‌ها را طبقه‌بندی و در دفتر درست ثبت می‌کند.

- **واحد پول:** ریال (مبالغ صحیح)
- **تاریخ‌ها:** رشتهٔ شمسی (مثل «۱۴۰۵/۰۹/۰۲»)، دقیقاً مثل شیت‌های قبلی
- **پشته:** Node.js + Express، دیتابیس SQLite تک‌فایلی (`data/farzam.db`)، احراز هویت JWT — بدون مرحلهٔ بیلد برای فرانت‌اند

## نصب سریع (Docker — راه پیشنهادی)

```bash
cp .env.example .env
# مقادیر .env را ویرایش کنید: ADMIN_EMAIL ،ADMIN_PASSWORD ،JWT_SECRET ،PIP_AGENT_API_KEY
docker compose up -d --build
```

بعد مرورگر را باز کنید: **http://localhost:3000**

اولین ورود با همان `ADMIN_EMAIL` / `ADMIN_PASSWORD` داخل `.env` است (کاربر مدیر در اولین اجرا به‌صورت خودکار ساخته می‌شود).

## نصب بدون Docker (Node.js 18+)

```bash
cp .env.example .env   # و ویرایش مقادیر
npm install
npm start              # http://localhost:3000
```

## متغیرهای محیطی (.env)

| متغیر | توضیح |
|---|---|
| `PORT` | پورت سرور (پیش‌فرض ۳۰۰۰) |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | حساب مدیر اولیه (فقط در اولین اجرا ساخته می‌شود) |
| `ADMIN_NAME` | نام نمایشی مدیر (اختیاری) |
| `JWT_SECRET` | راز امضای توکن‌های ورود — یک رشتهٔ تصادفی بلند |
| `PIP_AGENT_API_KEY` | کلید API ایجنت Pip (هدر `Authorization: Bearer <key>`) |
| `SEED_DEMO` | اگر `true` باشد چند ردیف آزمایشیِ برچسب‌خورده با «نمونه» ساخته می‌شود (پیش‌فرض: خاموش) |

## نقش‌ها

| نقش | دسترسی |
|---|---|
| `admin` مدیر | همه‌چیز + ساخت کاربر |
| `finance` مالی | ثبت و ویرایش دفاتر، دفاتر کل، داده‌های پایه، دانش + طبقه‌بندی رویدادها |
| `employee` کارمند | ساخت رویداد ورودی + مشاهده |
| `viewer` مشاهده‌گر | فقط مشاهده |

نوشتن در دفاتر فقط برای مدیر و مالی است؛ ساخت رویداد برای کارمند هم باز است.

## ماژول‌ها

پنل دقیقاً ۱۲ تب دارد، هم‌ساختار با پنل مرجع: داشبورد، ورودی یکپارچه، مانیتورینگ و تحلیل، هزینه‌ها، مشتریان، دفاتر و چک‌ها، حقوق و دستمزد، درآمدها، کالاها، وظایف، پرسش‌های مدیریت، دانش و قوانین.

- **داشبورد:** ۱۲ کارت شاخص با همان تعریف‌های پنل مرجع (هزینهٔ قطعی = جمع هزینه‌ها منهای ردیف‌های تکراریِ در انتظار تصمیم؛ تراز = درآمد − هزینهٔ قطعی − حقوق)، بنر طلایی کانال یک‌پیامی، نمودار جریان مالی و دونات دسته‌ها، دفاتر باز. زیرعنوان هدر وضعیت داده را گزارش می‌کند (چه خوانده شد و کدام ماژول‌ها خالی‌اند)، نه ساعت را.
- **ورودی یکپارچه:** فهرست رویدادها با دکمهٔ طبقه‌بندی (هزینه/درآمد/حقوق/نامشخص) — طبقه‌بندی، ردیف دفتر متناظر را می‌سازد
- **مانیتورینگ و تحلیل:** نوار شاخص‌های کلیدی، نمودار جریان مالی و سهم دسته‌ها، هزینه به تفکیک شخص (با نوار سهم)، شاخص‌های کیفیت داده، هشدارهای خودکار از روی شکاف‌های واقعی داده و یک پاراگراف تحلیل قاعده‌محور که همهٔ اعدادش از همان رکوردها حساب می‌شود
- **دفاتر:** هزینه‌ها، درآمدها، حقوق (ثبت + تغییر وضعیت بررسی)
- **دفاتر و چک‌ها:** دریافتنی، پرداختنی، چک (با شمارهٔ صیادی)
- **داده‌های پایه:** مشتری‌ها و کالاها
- **وظایف:** تعریف وظیفه برای کارمندها (عنوان، مسئول، مهلت، جزئیات) با چیپ وضعیت رنگی؛ هر کارمند می‌تواند وضعیت را به‌روز کند و گزارش انجام کار بنویسد. API ایجنت هم خواندن/ساخت/به‌روزرسانی وظایف را دارد (`/api/agent/tasks`)
- **پرسش‌های مدیریت:** ۲۰ پرسش رسمی بخش مالی در جدول جدا (`questions`)، گروه‌بندی‌شده، با فرم پاسخ برای هر پرسش؛ پاسخ ثبت‌شده وضعیت را «پاسخ داده شد» می‌کند. در اولین اجرای نسخهٔ جدید، پرسش‌ها به‌صورت خودکار و idempotent از روی `data/questions-seed.json` ساخته می‌شوند و مدخل‌های متناظرشان از پایگاه دانش حذف می‌شوند تا دانش فقط قواعد و یافته‌ها بماند (پرسش واحد پول از قبل با پاسخ «ریال» ثبت شده است، پس ۱۹ پرسش باز می‌ماند)
- **دانش و قوانین:** قواعد، پاسخ‌های مدیریت و یادداشت‌ها

## عکس رسید

در فرم «ورودی یکپارچه» و فرم‌های ثبت هزینه، درآمد و حقوق می‌توان عکس رسید یا فیش را هم پیوست کرد:

- عکس در مرورگر به‌صورت خودکار فشرده می‌شود (حداکثر بُعد ۱۲۰۰ پیکسل، JPEG با کیفیت ۰٫۸۲) و به‌صورت data URL **همراه خود رکورد** در دیتابیس ذخیره می‌شود — فایل جداگانه‌ای روی دیسک نیست.
- پیش‌نمایش عکس همان لحظه در فرم دیده می‌شود و رکوردی که عکس دارد خودکار وضعیت رسیدش «دارد» می‌شود.
- در جدول دفاتر، کنار هر رکوردِ دارای عکس یک بندانگشتی نمایش داده می‌شود؛ با کلیک روی آن، عکس در اندازهٔ کامل باز می‌شود.
- رویداد ورودی هم عکس را نگه می‌دارد و هنگام طبقه‌بندی، همان عکس به ردیف دفتر ساخته‌شده منتقل می‌شود.
- بدون عکس، رفتار دقیقاً مثل قبل است: رکورد با وضعیت «رسید ندارد» ثبت می‌شود.

## دسترسی ایجنت (Pip)

ایجنت با صفحهٔ وب کار نمی‌کند؛ از API زیر `/api/agent/*` با کلید جدا استفاده می‌کند و **هر نوشتن ایجنت در جدول `audit_log` ثبت می‌شود**. جزئیات: [docs/agent-api.md](docs/agent-api.md) و [docs/access-for-pip.md](docs/access-for-pip.md).

## وبهوک تلگرام

`POST /api/telegram/webhook` آپدیت تلگرام را می‌گیرد (متن/کپشن + `file_id` عکس) و به‌صورت یک رویداد پردازش‌نشده ذخیره می‌کند. هیچ تماس خروجی به تلگرام زده نمی‌شود؛ آدرس وبهوک را با BotFather یا `setWebhook` روی همین مسیر تنظیم کنید.

## داده و بکاپ

همه‌چیز در `data/farzam.db` است (در Docker روی ولوم `./data` ماندگار می‌ماند). برای بکاپ کافی است همین فایل کپی شود. فایل دیتابیس، `.env` و `node_modules` در `.gitignore` هستند و وارد گیت نمی‌شوند.

## امنیت

- هیچ رازی در کد نیست؛ همه از `.env` خوانده می‌شود و `.env` نباید کامیت شود.
- کلید ایجنت را در چت نفرستید؛ از مسیر امن اتصال Muse تحویل دهید (نگاه کنید به docs/access-for-pip.md).
- پشت HTTPS (دامنه + reverse proxy) اجرا کنید و `JWT_SECRET` و کلید ایجنت را تصادفی و بلند انتخاب کنید.

## استقرار روی Vercel (ساده‌ترین راه)

روی Vercel فایل دیتابیس لوکال ماندگار نیست؛ پس دیتابیس را روی Turso (رایگان) می‌گذاریم و اپ از راه دور به آن وصل می‌شود. کل کار حدود پنج دقیقه است:

۱. **دیتابیس Turso:** در [turso.tech](https://turso.tech) ثبت‌نام کنید → Create Database → یک نام (مثلاً `farzam-erp`) → از صفحهٔ دیتابیس، `Database URL` (با `libsql://` شروع می‌شود) و یک `Auth Token` بگیرید.

۲. **پروژه Vercel:** در [vercel.com](https://vercel.com) با حساب گیت‌هاب وارد شوید → Add New… → Project → مخزن `farzam-erp` را Import کنید (تنظیم خاصی لازم نیست؛ `vercel.json` داخل مخزن است).

۳. **متغیرهای محیطی** (در همان صفحهٔ Import یا Settings → Environment Variables):
   - `ADMIN_EMAIL` و `ADMIN_PASSWORD` — ورود اول مدیر
   - `JWT_SECRET` — یک رشتهٔ تصادفی بلند
   - `PIP_AGENT_API_KEY` — یک کلید تصادفی بلند برای ایجنت
   - `TURSO_DATABASE_URL` و `TURSO_AUTH_TOKEN` — از قدم ۱

۴. **Deploy** را بزنید. پنل روی آدرس `….vercel.app` بالا می‌آید و با ایمیل/رمز مدیر وارد می‌شوید.

نکته‌ها: بدون دو متغیر Turso، داده‌ها روی Vercel ذخیره نمی‌مانند. روی پلن رایگان (Hobby) طبق قوانین Vercel استفادهٔ تجاری مجاز نیست؛ برای استفادهٔ واقعی شرکت، پلن Pro لازم است. مسیر Docker/VPS بدون Turso هم سر جایش است و با فایل داخلی کار می‌کند.
